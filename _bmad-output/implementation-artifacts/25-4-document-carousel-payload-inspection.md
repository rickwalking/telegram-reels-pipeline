# Story 25.4: Document Carousel & Payload Inspection

Status: ready-for-dev

## Story

As a System Operator,
I want to inspect the exact JSON payloads and markdown artifacts generated by agents at each stage,
So that I can verify the quality of their work directly from the UI.

## Acceptance Criteria

1. **Given** a pipeline run with completed stages, **When** I select a stage in the Run Detail or DVR view, **Then** the UI must display a "Document Carousel" showing all artifacts for that stage.

2. **Given** the Document Carousel, **When** viewing a JSON payload, **Then** it must render with syntax highlighting, collapsible sections, and a search function.

3. **Given** the Document Carousel, **When** viewing a markdown artifact, **Then** it must render as formatted markdown with proper headings, code blocks, and lists.

4. **Given** any artifact in the carousel, **When** I click "Copy", **Then** the raw content must be copied to the clipboard, **And** a visual confirmation must appear.

## Dev Notes

### Document Carousel UX

The Document Carousel is the primary way operators verify agent work quality. It must be:
- **Fast**: JSON payloads are typically 1-50KB, inline in the API response
- **Readable**: syntax highlighting and collapsible sections for large payloads
- **Comparable**: easy to switch between stages to compare inputs/outputs
- **Exportable**: copy buttons for pasting into bug reports or discussions

### Artifact Type Detection

```typescript
const ARTIFACT_TYPE_MAP: Record<string, 'json' | 'markdown' | 'binary'> = {
  '.json': 'json',
  '.md': 'markdown',
  '.txt': 'markdown',  // treat plain text as markdown
  '.mp4': 'binary',
  '.png': 'binary',
  '.jpg': 'binary',
};
```

### Performance

For the typical pipeline run, each stage produces 1-3 artifacts (JSON + optional binary). The carousel should lazy-load binary artifacts (only fetch when tab is selected) but eagerly load JSON/markdown since they're small.
